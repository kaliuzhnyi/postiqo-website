# VIN enrichment for Digital Cards

Implemented on 15 October 2026. NHTSA data is stored in `inventory_enrichment`, one row per `inventory.id`. Publisher continues to upload and download its original fields. Website readers fill only blank source fields and display the additional specifications in compact groups.

## Ownership and data flow

- Shared D1 schema: Publisher licensing migration `0013_inventory_enrichment.sql` in `postiqo-publisher/cloudflare-workers/licensing/migrations/`.
- Background worker: `cloudflare-workers/cards/src/vin-worker.js`, deployed with `wrangler.vin.jsonc`.
- Normalization and source priority: `cloudflare-workers/cards/src/vin.js`.
- Public reader and grouped presentation: Cards `src/index.js`, `src/render.js`, `src/card.css` and `src/card-client.js`.
- Static phone preview: `/products/postiqo-cards/demo/`, regenerated by `node scripts/generate-cards-demo.mjs`.

The decoder never updates source inventory, its timestamps/hash, or dealer snapshot revisions. No change to desktop Publisher, its local database, the upload allowlist, or `/v1/inventory/read` is required. Server migration and Cards deployment must be ordered as described below.

## Only active inventory is decoded

One Cron Trigger runs every 15 minutes. A durable cursor scans at most 20 active inventory rows by indexed ID per run. This covers both existing and newly uploaded cars without a mass backfill or a full-table scan on every tick. An unchanged completed result is left alone.

The job then attempts at most three queued records, with at most one NHTSA batch request. Repeated delivery of the same 15-minute slot does not process another batch. A singleton lease prevents overlapping runners, and per-record tokens prevent a late response from replacing newer work.

Activity is checked during discovery, when claiming a job, immediately before the API request, and when saving the response. If a car becomes inactive while NHTSA is responding, that response is discarded. Existing completed data remains stored when a car becomes inactive. A previously skipped inactive job can be rediscovered if the car becomes active again and has not exhausted its attempts.

A change of VIN/year invalidates the old context and is picked up by the scan. The reader suppresses a mismatched result immediately. Price, mileage, photos and ordinary repeated uploads do not invalidate VIN data. A VIN added to a stock-only source record follows Publisher's existing new-key behavior; records are not merged by stock number.

With 202 active vehicles, the scan completes a cycle in 11 ticks, about 2 hours 45 minutes. Successful decoding at three cars per tick takes about 17 hours for the initial backlog. New cars and reactivations are discovered within a scan cycle and then wait behind existing work. Provider outages, warnings and retries extend those times. These are deliberately modest defaults, not an instant-enrichment promise.

## Fields and precedence

Blank means null, absent, or a string containing only whitespace. Existing zeroes and explicit values such as `Other` are not automatically treated as blank. A filled dealer value always wins; if it becomes blank on a later import, the saved VIN fallback is available again.

| Existing field | NHTSA input |
| --- | --- |
| year, make, model, trim | ModelYear, Make, Model, Trim |
| body_type, vehicle_type | BodyClass, VehicleType through explicit mappings |
| cylinders, drivetrain | EngineCylinders, DriveType |
| transmission | TransmissionStyle through explicit mappings |
| fuel_type | ElectrificationLevel plus primary and secondary fuel |

Additional website fields are engine displacement in litres, engine model/configuration, transmission speeds, doors, seats, seat rows, electrification level, secondary fuel, and assembly country. The table stores these as validated keys in `decoded_json`, alongside the fallback fields, so future optional fields do not require widening the Publisher contract.

Price, mileage, availability, condition, stock number, colours, photos, description and contacts cannot be overwritten by decoded JSON. Unknown numeric values stay absent. Optional equipment, battery capacity and total hybrid power are not inferred. A PHEV whose primary fuel is Electric is classified as Plug-in hybrid. Make/year conflicts suppress the enrichment; model matching also recognizes the decoded Series, including BMW 3 Series versus 330e.

Cards explicitly project only approved public values. The raw provider response, error codes, job states and lease tokens are never returned. Access remains scoped to the dealer and `cards_enabled`.

## Compact specifications

The card presents three groups, omitting empty rows and empty groups:

1. Vehicle: year, make, model, trim, mileage, condition and stock number.
2. Engine & transmission: engine size/cylinders, drivetrain, transmission/gears, fuel, electrification and engine details.
3. Body & cabin: exterior and interior colours together, body style, doors, seating and assembly country.

The existing 60-second refresh also updates these groups using DOM text nodes. It does not add another polling request or reset edited payment-calculator inputs. Headings, photos and description still refresh when the page is reopened. The static demo uses illustrative specifications for a fictional vehicle and makes no live inventory or VIN requests.

## Provider validation and retry limits

Only complete 17-character VINs using `[A-HJ-NPR-Z0-9]` are sent. Stock-only or malformed VINs finish as `skipped`. This does not reject the original inventory upload.

The worker calls the fixed HTTPS NHTSA batch endpoint with only VIN and a known year. It rejects redirects, limits the response to 128 KiB, limits each stored raw result to 32 KiB, matches rows by VIN, and rejects missing or duplicate matches. Identical VIN/year lookups within one batch are shared across dealers; different year hints for the same VIN are deferred to separate batches.

Automatic application requires the parsed error-code set to be exactly `{0}`. Codes 7/8 finish as `no_data`; VIN warnings or errors finish as `review`. Suggested VIN corrections are never applied automatically. Clean but incomplete results finish as `partial` and are not repeatedly fetched.

Transient network/response failures and HTTP 429/5xx receive at most three attempts per context. Retry delays are one hour then six hours, extended by Retry-After. Provider-wide failures also apply a shared cooldown, so the worker does not repeatedly send the next cars during an outage. Permanent HTTP failures finish as `failed`. After a crash, an expired processing lease is eligible again within the same attempt limit.

NHTSA is free and does not require an API key. Its coverage is oriented to vehicles intended for the US market; Canadian-only models can have limited information. See the [NHTSA API](https://vpic.nhtsa.dot.gov/api/Home/Index), [FAQ](https://vpic.nhtsa.dot.gov/api/Home/Index/FAQ) and [error codes](https://vpic.nhtsa.dot.gov/api/vehicles/GetVehicleVariableValuesList/Error%20Code?format=json).

## Free-tier resource budget

The implementation uses the existing D1 database and one scheduled Worker. It adds no Queue, KV namespace, paid service, new plan, or third-party subscription. The hard limits in code are 96 scheduled slots/day, 20 scanned active rows/slot, three attempted records/slot, and three attempts/context. At most 288 VIN attempts and 96 NHTSA HTTP requests are made per day; completed data requires no external call.

A workerd test with real local D1 and 202 fixture rows measured 165 rows read and 52 rows written for the first run, including the final runner update. Repeating that measured workload for all 96 slots would be 15,840 reads and 4,992 writes/day. This is a workload estimate, not a guaranteed account-wide maximum. Record age, indexes, retries and other applications affect actual usage; the Worker records each run's D1 counters for inspection. Once the backlog is complete, calls and writes drop substantially. Reading an enriched card adds an indexed lookup, with no extra browser polling.

Cloudflare's Free allowance is 5 million D1 rows read/day, 100,000 rows written/day, 500 MB/database and 5 GB/account. Workers Free permits 100,000 invocations/day and 10 ms CPU/invocation; I/O waiting is different from CPU time. These limits are shared with existing applications. The new job's modest budget leaves most of the row allowance available, but current total account usage must still be monitored. Free-plan quota exhaustion causes errors rather than automatically buying an upgrade. No plan upgrade is part of this change. [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).

The live database inspected before deployment contained 285 vehicles, 202 active and 83 inactive, and occupied about 1.8 MB. A maximum-size 32 KiB raw response for every active car would add about 6.6 MB before normalized data and indexes. Actual provider responses are normally smaller; storage should still be checked as inventory grows.

## Deployment and operations

1. Test the Publisher licensing migration and the Cards/decoder suites. Keep `tests/enrichment-schema.sql` byte-for-byte aligned with the owning migration.
2. Apply `0013_inventory_enrichment.sql` to `postiqo-licenses` through the Publisher licensing migration tooling. It creates empty extension tables and indexes; it does not copy or rewrite existing vehicles.
3. Build and deploy the Cards Worker, then deploy `wrangler.vin.jsonc`. The scheduled job will discover the existing active vehicles incrementally.
4. Regenerate and publish the static demo for phone preview. Confirm the three groups on a narrow viewport and normal public Cards access.

Set `VIN_ENRICHMENT_ENABLED=false` and redeploy the VIN Worker to pause decoding without removing saved results. There is no public HTTP endpoint that can start a job or bypass its rate cap. For rollback, restore the earlier Cards version and disable the scheduled worker; the additive tables can remain.

Useful read-only operational queries:

```sql
SELECT status, COUNT(*) AS vehicles FROM inventory_enrichment GROUP BY status;
SELECT scan_cursor, last_run_at, cooldown_until, last_attempted,
       last_rows_read, last_rows_written
FROM inventory_enrichment_runner WHERE id = 1;
```

The runner's stored counters exclude its final metrics update, which adds one row write. Full database/account usage is available in Cloudflare metrics. Failed/review rows are retained for diagnosis; they do not restart every day. An intentional retry can reset a specific active record to pending with attempts zero through authorized database administration, after correcting its cause.

Validation covers source priority and isolation, old active inventory, inactive records, a sale during a request, VIN/year changes, malformed responses, warning codes, retries/cooldowns, duplicate slots, expired leases, dealer deduplication, Publisher re-upload/feed compatibility, public field allowlists, grouped live refresh and 320px-to-desktop layouts.
